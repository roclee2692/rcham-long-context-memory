# 第零轮：层级压缩索引的导航预实验

已于 2026-09-14 在本机运行。这是无训练的合成向量实验，检验“平均摘要能否给原始记录指路”，没有训练语言模型，也没有证明语义压缩或替代 Attention 成功。

## 实验怎样做

- 每条记录有一个 64 维向量和确定的证据 ID；原始记录完整保留。
- 每 16 条记录取均值形成一个摘要；每 4 个摘要继续向上合并，建立树。
- 索引全部建立以后，才生成问题向量：目标记录向量加独立噪声。问题不参与建树。这是近邻查找，尚未检验自然语言问题编码能力。
- 平坦方法给所有叶块摘要打分，选出若干块；树形方法逐层筛选，整层最多保留指定数量候选。
- 最后读回候选块中的原始记录。召回成功表示目标证据出现在读回集合中。另记录精确向量匹配结果，这不是语言模型答题准确率。
- 长度为 256、1,024、4,096 条记录；每个长度和场景包含 9 段历史，每段 20 个问题。合计 1,620 个场景—问题实例，其中主题聚集和打散复用了问题，不能称为 1,620 个独立样本。

## 主要结果

以下均为 **4,096 条记录，最终读回 4 个块、共 64 条原始记录**。每格 180 个问题，来自 9 段历史。百分比是证据召回率。

| 数据排列 | 扫描全部叶块摘要 | 分层搜索，每层最多留 4 个候选 |
|---|---:|---:|
| 完全随机向量 | 37.22% | 17.78% |
| 相同主题放在一起 | 72.78% | 72.78% |
| 同一批主题数据打乱顺序 | 12.22% | 8.89% |

平坦方法每题给 256 个摘要向量打分，树形方法给 52 个向量打分，两者随后均给 64 条原始记录打分。

全扫描原始记录的参考方法在这些配置下均为 100%，但它读取 4,096 条记录，不是同预算对手。“原始全扫描召回率”因读取全部记录本来就必定为 100%；此外它在本次配置下的最高分记录也都正确，说明所造问题能够通过完整向量匹配解决。

## 怎样理解

1. **省打分次数不自动带来高召回。**随机或混杂数据里，简单均值会把定位信号冲淡，上层剪枝造成额外遗漏。
2. **分组方式影响很大。**主题聚集与打散使用同样记录、ID、值和问题，只改变顺序；因此它们之间的差异可以归因于分组对这套均值索引的影响。但按生成器已知主题排序是有利条件，不表示真实模型已经会发现这种分组。
3. **没有测到这套 Python 树实现比平坦实现更快。**4,096 条记录时，平坦与树形的查询中位耗时约 0.012–0.013 ms 和 0.018 ms。树减少了向量比较，但多了逐层调度和数组操作。没有专门进行随机执行顺序、预热和硬件性能实验，时间仅作原型诊断，不能外推 GPU 加速。
4. **原文保留并不能保证可访问。**`error_trace.json` 保存了一个目标仍在档案、平坦方法找到、树形方法在中间层剪掉目标祖先的具体案例。

这个结果支持优先研究更好的压缩表示和导航信号；不支持“已经证实整体架构有效”，也不能用来否定训练后的压缩器。

## 空间和公平性

- 平坦与树形方法共用完全相同的整棵索引，便于隔离遍历策略。实际部署的平坦方法不必保存内部节点，因此不能据此宣称两者最小空间成本相同。
- 账本计入各层 float32 向量载荷和原始向量、ID、值。树的位置关系可由整数算术得到。Python 对象、分配器、临时数组以及更复杂元数据未计入，不能称为总进程内存。
- 原始档案完整保留，总存储是档案加索引。本试验没有实现总空间压缩。
- `tree_beam_4` 和 `flat_4` 都读 64 条，读取预算匹配；`tree_beam_4` 和 `tree_beam_1` 分别读 64 和 16 条，其差异是预算取舍。
- 附带置信区间以整段历史重采样，保留同一历史问题的相关性。9 段历史属于小型先导实验，区间仅供描述；有序与打散的配对条件也不能算作独立重复。

## 文件和复现

- `probe.py`：完整脚本，只依赖 Python 3 和 NumPy。
- `report.json`：参数、版本、汇总、局限及按历史配对的 bootstrap 区间。
- `summary.csv`：各长度、场景、方法的汇总。
- `per_query.csv`：每题的召回、读取量和耗时。
- `per_history_index.csv`：建树成本、向量存储账本、规范化档案哈希。
- `error_trace.json`：可追溯失败案例。

在本目录运行即可；结果写到新的目录，保留已交付结果：

```bash
python3 probe.py --output-dir ./rerun
```

随机种子和实验规模写在脚本顶部 `CONFIG`。召回结果应可重现，耗时随运行环境变化。脚本包含查询配对、原始读取预算和错误轨迹检查。
