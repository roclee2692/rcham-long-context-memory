# 架构设计 v0.1：局部注意力与可回溯层级记忆

留档日期：2026-09-14。状态：概念架构与机制假设；只有简化的导航预实验已经运行。

## 1. 核心目标

降低长序列全局 Self-Attention 的两两交互成本，同时保留长期信息的可访问性。局部窗口负责精确处理，多尺度表示负责更大范围的理解，历史细节通过层级导航按需返回模型计算。

核心是 CNN 式的“局部—层级—整体”组织与反向回读的统一设计：**理解时向上压缩，回忆时沿同一层级向下展开。**长期存储是这个计算架构的一部分。

## 2. 用户提出的原始架构要素

1. 每个小窗口内做精确 Attention，减少所有历史 token 持续两两计算。
2. 逐级组合局部表示，形成更大的语义范围：token → 短语或句子 → 段落 → 事件 → 主题 → 全局状态。
3. 旧内容逐渐降低活跃分辨率：原始内容 → 关键内容 → 摘要 → 状态 → 索引。
4. 高层节点保存到低层节点与原始内容的入口，压缩不等于切断细节访问。
5. 工作记忆保存当前精确内容；长期记忆保存较低成本的历史表示。
6. 检索利用语义、实体、时间、地点、关系、因果和状态变化等线索。
7. 先定位记忆锚点，沿层级或相关关系展开；必要时读取原始 token。
8. 保存状态快照与中间增量变化，支持恢复指定历史时刻。
9. 对重要、常用、可能影响后续的内容保留较高精度和较长活跃时间。
10. 回读内容送回当前上下文或模型记忆接口，参与后续理解和生成。

“句子、事件、主题”是设计直觉，v0.1 尚未规定这些语义层必然由训练自动形成。

## 4. 模块与节点契约

| 模块 | 输入与输出 | v0.1 约束 |
|---|---|---|
| 局部编码 | 当前窗口 → 局部细节表示 | 仅访问已出现内容；窗口及边界策略待实验 |
| 层级聚合 | 若干低层节点 → 高层节点 | 同时保留指向子节点的关系；所有层均计入空间 |
| 工作记忆 | 当前窗口、高层概况、回读细节 → 当前计算状态 | 热端容量和实际读取量有预算 |
| 导航器 | 当前隐藏状态或问题表示 → 候选节点 | 候选数按整层全局限制；所有打分及回退计费 |
| 细节读取 | 选中节点 → 子节点、原文或已保存的 KV | 每次只取所需范围；保留来源位置与时间信息 |
| 状态存储 | 状态快照和增量事件 → 指定时刻状态 | 增量顺序、版本、生效时间明确；不把推测写作原始证据 |
| 记忆调度 | 当前需求、重要度、容量 → 热冷迁移与保留精度 | 重要度不是只按词频；具体学习方式待验证 |

建议的节点结构（字段为概念，不要求直接使用此 JSON 作为底层实现）：

```json
{
  "node_id": "稳定标识",
  "level": "层级",
  "source_range": "覆盖的原始位置范围",
  "content_vectors": "用于理解整体的有限表示",
  "routing_vectors": "用于寻找细节的有限导航表示",
  "children": "子节点入口",
  "cross_links": "少量有来源的跨节点关系",
  "archive_pointer": "原始内容或KV的位置",
  "valid_time": "内容或状态的时间范围",
  "version": "版本",
  "retention_state": "精度、重要度、存储层级"
}
```

将内容表示与导航表示分开、采用多个导航向量，是后续优化建议，尚未实现或证明优于单表示。

## 5. 写入与回忆流程

**写入**：当前文本进入局部窗口；完成的窗口形成低层节点；节点逐层聚合，保留原始范围与孩子入口；新内容只更新受影响的层级部分。活跃细节移到长期存储时，降低热端成本，但不自动删除原始档案。

**回忆**：根据当前需要形成导航查询，先看少量高层表示，再逐层筛选候选。问题只需要大意时可停在高层；需要准确值、条件或原话时继续读到低层。允许有限候选束和少量关系跳转，避免单一路径过早剪掉正确分支。

**反馈**：回读信息与局部信息共同参与当前计算，必要时修正当前高层判断。修正先保存在当前工作状态；更新持久节点时要保留来源与版本。

**状态重建**：目标时间之前的快照，加按顺序发生的增量，得到该时刻的已记录状态。文本原文、模型 KV、显式状态是不同对象：状态可由明确事件重放，不意味着有损摘要能无损逆推出所有 token，也不意味着重编码一小段文本能还原原模型当时的 KV。

## 6. 从 CNN 借鉴什么、怎样适配文本

保留局部感受野、逐层聚合、多尺度信息和细节旁路。文本的关系会跨越相距很远的段落，因此需要原始顺序、跨窗口联系，以及少量定义—使用、规则—例外、实体—版本连接。

第一版优先采用规整或少数几档窗口，并动态调整每块保留的表示数量；是否改成完全动态边界，需要精度与硬件效率共同验证。信息难预测不等于未来重要，一个简单的否定词也可能决定答案。

## 7. 时间与空间复杂度：条件而非承诺

下述简式先把隐藏维度和模型层数视作常量：

- 窗口宽度为固定 w 时，局部 Attention 的整体交互量约为 O(nw)。窗口重叠、额外通道会增加实际常数。
- 若每层以固定比例 r > 1 缩小且每节点处理成本有界，节点总量 n + n/r + n/r² + … 为 O(n)。任意一层重新做不受限的全局 Attention 会改变总成本。
- 若树的分支数固定、每层全局候选束宽度有界，一次由根到叶的导航可以只打分 O(log n) 个量级的节点；相应召回率没有最坏情况保证。
- 若每个 token 都做一次上述搜索，整段导航可为 O(n log n)。共享候选或减少搜索频率可能降低常数，但效果与因果性需要检验。
- 允许展开更多分支、回退、全扫描时，必须计入这些成本；不能只用树深度证明近线性总计算。
- 完整原文或完整 KV 仍保留时，总档案空间随历史增加。热端变小不能当作总存储减少。

整模账本应包含局部计算、所有层聚合、导航、实际读回、状态重放、缓存管理和存储搬运。训练、输入处理、逐 token 生成分别测量。

## 8. 可验证的训练方向

第一步隔离可训练压缩器、导航器与读取器：写入阶段不看未来问题，读取阶段通过任务结果提供训练反馈。先比较压缩表示直接使用，再单独比较允许原文回读的效果。

第二步才接入自回归模型：预测当前位置时不能访问含未来信息的高层节点。离线建立整篇文档索引用于后续问答，与在线生成必须分别设置对照。

阅读器可能在标准证据给定时仍然答错，所以同时评估证据集合召回与答案质量。未来实验还需匹配存储预算、读取预算、模型规模与训练投入。

## 9. 已有证据与尚未验证部分

已运行：NumPy 合成向量、均值摘要、规则四叉树、平坦与候选束搜索。最新结果和具体参数见 [预实验报告](../outputs/compression_probe/README.md)。

## 10. 相关工作与可复用机制

以下仅记录讨论中已核对的参考方向，未声称本项目已复现其成绩，也未完成覆盖全部相关工作的创新性审查：

- [ConvMem](https://arxiv.org/abs/2609.10441)：已知问题条件下的层级文本汇总与细节旁路；不同于未来问题未知的持续记忆写入。
- [HiLS](https://arxiv.org/abs/2607.02980)：学习型块选择与分层注意力融合；可参考训练反馈设计，其原文仍保留扫描所有块摘要的计算项。
- [H²MT](https://arxiv.org/abs/2605.24930)：离线语义层级记忆与粗到细读取；可参考节点聚合和路径监督。
- [ZoomR](https://aclanthology.org/2026.acl-long.76/)：利用摘要索引按需读取细粒度 KV；可参考回读接口。
- [SPIN](https://arxiv.org/abs/2604.26837)：稀疏访问与分层 KV 存储的执行设计；可参考搬运账本。

后续版本要围绕可测量的增量贡献收窄论文主张。完整架构是研究目标；具体有效性由实验逐项建立。
